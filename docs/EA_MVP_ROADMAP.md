## EA-0 read-only inventory and decision

The existing `PositionObservation` schema contains only visibility, lane and current position. `HeadlessManiaTapAdapter.run` consumes all observations and policy actions **before** calling `environment.play`; it therefore cannot deliver a newly judged label back to the fly during an episode. `GameFeedbackCursor` filters a completed `GameResult` by availability time, which is useful for event-contract checks but not by itself a live feedback source. The separate `ManiaGame` exposes incremental game time and key actions, so an external orchestrator can implement the missing causal loop while leaving the saved game source intact. Existing L0.4 direct-weight intervention passed engineering capacity for one isolated note but did not learn; L0.6 found the chosen biological teaching interpretation unsupported. This inventory establishes a feasible software seam, **not** fly-learning readiness.

**EA-0 PASS scope:** source inventory and separate specification exist; no component was wired, simulated or trained. The highest-priority unresolved question is whether the user accepts the explicitly engineered sensory, readout, electrical and judgement→DAN boundaries for this separate claim track. EA-1 is therefore the sole next stage. Implementing the bridge first would otherwise leave its learner-facing contract ambiguous.

## EA-1 stage specification — approval received

1. **Stage ID/name:** EA-1 — assumption approval and freeze plan.
2. **Question:** Which exact fixed interfaces and bounded parameter-selection procedures may define an engineering-assumption learner without being mistaken for a biological result?
3. **Why next:** Strict B3/B3.1 could not propagate selected adult weights to a first key action, Level 4D failed target acquisition, and L0.6 found no supported game-judgement→DAN rule. The current adapter also withholds judgements until after policy execution. Those gaps cannot be silently crossed.
4. **Hypothesis/outcomes:** Approval of explicit bounded rules allows an EA-only implementation plan; rejection keeps EA-2 and later work held; an underspecified or score-selected value is inconclusive and must be revised before use.
5. **Intervention:** Present EA-01–EA-07 individually with exact candidate values or bounded selection rules, evidence, source identities, and permitted claim wording. No neural or game run.
6. **Controls:** Preserve all strict reports and raw receipts; preserve the saved recreation and Freedom Dive comparison; keep source graph immutable and all currently uncommitted user work intact.
7. **Primary endpoint:** An approved, versioned EA assumption manifest that completely specifies the candidate and task-independent selection gates before any dependent test.
8. **Secondary endpoints:** Explicit unknowns, compatibility with the existing 1-ms position seam, and feasibility of a streaming judgement source.
9. **Predeclared interpretation:** PASS only with explicit user approval for each applied assumption and no score-driven choice; FAIL for rejected or outcome-selected assumptions; INCONCLUSIVE when exact values/procedures remain unchosen.
10. **Do not:** Run training, confirmation, parameter sweeps against game score, biological-claim substitution, or edits to strict results or the playable recreation.
11. **Output:** Approved assumption manifest, source/config hashes, EA-1 decision note and process-log update.
12. **Stop condition:** Stop after the EA-1 decision. EA-2 is separately proposed, not automatically run.

The user approved the EA-01/EA-02 interface bundle and the other listed engineering-assumption categories. EA-01 currently reuses the source-order set of 32 audited KCs, preferred positions `i/31`, Gaussian tuning `exp(-0.5*((x-mu)/0.08)^2)`, peak artificial KC drive `1.2 mV-equivalent`, and a `1,000 µs` observation/integration tick. EA-02 currently reuses the fixed inverse MBON05 readout: after the first positive MBON05 response, close `0.05`-wide current-position bins causally; press once when a bin's maximum MBON05 voltage is at or below the existing pretraining-probe threshold `0.005572335995331903 mV-equivalent`; release `10,000 µs` later. These are **ENGINEERING ASSUMPTIONS**, not measured fly sensing or motor output. The threshold came from a task-independent local-weight probe in Level 2, while Level 4D still failed its target-action gate. Exact EA-05/EA-06 teaching and learning choices remain open and no training has run.

## EA-3.1 completed stage specification and decision

1. **Stage ID/name:** EA-3.1 — no-cue and MBON-output attribution.
2. **Question:** Does the same selected-weight perturbation cause its first DOWN through a changed MBON response, while a genuine no-cue run and an MBON-output-off run stay silent?
3. **Why next:** EA-3's frozen task-free panel passed its behavioral subgate, but the receipt does not include the source-tagged MBON voltage/input trace or the two negative controls needed for full pretraining admission.
4. **Hypothesis/outcomes:** A matched neural response change, readout change and loss of DOWN with MBON output disabled support this reduced-circuit causal route; a background/no-cue DOWN or unchanged MBON response fails it; missing trace or unmatched starts are inconclusive.
5. **Intervention:** From a single frozen source config, compare no-cue, initial-cue, local-0.5 selected-weight, and local-0.5 with MBON output disabled. Record input drive, KC spikes, MBON voltage and readout bins on the same 500-ms 1→0 position trajectory where a cue exists. No game or teacher.
6. **Controls:** Keep source IDs, selected contact mask, all initial neural state, threshold, bin geometry, clock, weights outside the six selected KCs and all random streams fixed. Replay each arm exactly twice.
7. **Primary endpoint:** No DOWN in no-cue and output-off; selected-weight arm changes MBON bin response and emits a first DOWN near the predeclared 0.5 center; repeated ledgers exactly match.
8. **Secondary endpoints:** KC spikes, selected chemical arrival/voltage contrast, first positive MBON time, event counts and bounded queues.
9. **Predeclared interpretation:** PASS only if every primary condition holds. FAIL on any causal or background condition that does not hold. INCONCLUSIVE if source identity, event attribution or repeatability cannot be verified.
10. **Do not:** Change threshold/gain, choose another center, judge by game score, stimulate DAN, update synapses or train.
11. **Output:** Versioned protocol, raw per-arm traces, independent first-DOWN audit, short decision report and process-log update.
12. **Stop condition:** Record the result and stop. EA-4 remains a separate proposed teacher stage; no training follows automatically.

**Decision:** EA-3.1 PASS under the frozen primary gate. [Full result](EA_MVP_NO_CUE_OUTPUT_RESULT.md). The stage stops here; EA-4 is proposed only.

## EA-4 next stage specification — proposed only

1. **Stage ID/name:** EA-4 — fixed teacher contract and local-rule sanity.
2. **Question:** Can a disclosed game-judgement→DAN rule deliver post-outcome signals without hidden timing leakage and change only cue-eligible selected fly synapses in a one-pulse fixture?
3. **Why next:** EA-3 now shows non-learning control of a fixed key output; L0.6 established that biological game-to-DAN semantics are unsupported. EA-05/06 must therefore be made explicit and tested as engineering assumptions before any task training.
4. **Hypothesis/outcomes:** A label-only, causal DAN adapter and contact-local one-pulse update can pass; any early label, unselected update or wrong control fails; missing DAN/eligibility attribution is inconclusive.
5. **Intervention:** Freeze a complete judgement-label table, target DAN IDs, pulse schedule and bounded amplitude; freeze local eligibility time, rate and weight limits using task-free sanity criteria. Run event-order and one-pulse local-rule fixtures only.
6. **Controls:** Matched DAN-off, plasticity-off, eligibility-off, unpaired timing and no-result arms; same source graph, initial state and event clock.
7. **Primary endpoint:** No label reaches DAN before availability; only declared labels recruit declared DANs; only selected eligible contact slots change within frozen bounds; every negative control keeps weights unchanged.
8. **Secondary endpoints:** DAN spike times, selected KC eligibility, exact weight deltas, queue bounds and checkpoint replay.
9. **Predeclared interpretation:** PASS only if all causal/locality conditions hold. FAIL for leakage, uncontrolled changes or silent intended DAN pulses. INCONCLUSIVE for missing trace or nonreplayable state.
10. **Do not:** Run a multi-note learning curriculum, adjust values from game score, expose signed hit error/ideal note time to the teacher, or revise strict biology results.
11. **Output:** Versioned EA-05/06 manifest, raw one-pulse ledgers, independent audit, result report and process-log update.
12. **Stop condition:** Stop after EA-4, even on PASS. EA-5 development training remains prohibited by the user's current instruction.
